Threat Engine – Overview and Documentation
==========================================

1. Introduction
---------------
This Threat Engine is designed to analyze URLs and classify them according to potential security risks. It integrates multiple layers of analysis including static rule-based checks, machine learning, and optional behavioral and AI/rule-based models. 

The engine is implemented in Flutter/Dart and is structured to allow easy integration with the UI while remaining modular for future expansions.

---

2. Architecture and Pipeline
----------------------------

The engine is structured in **5 layers**, each handling a specific responsibility:

Layer 1: Feature Extraction (feature_extractor.dart)
  - Extracts numerical and boolean features from a URL.
  - Features include:
      * URL, domain, subdomain, and path lengths
      * Character counts: '.', '-', '_', '/', '?', '=', '&', '@', '%'
      * Boolean flags: has IP, has port, uses HTTPS, has query
      * Shannon entropy to detect randomness/obfuscation
  - Provides a feature vector for ML models.

Layer 2: Static Rules & Heuristics (static_rules.dart)
  - Applies predefined rules and heuristics to detect suspicious URL patterns.
  - Examples:
      * Presence of suspicious keywords or characters
      * Abnormal URL structure
      * Known blacklists (if included)
  - Outputs a list of detected threats with severity (low/medium/high).

Layer 3: Machine Learning Model (logistic_regression.dart)
  - Uses a **pre-trained logistic regression model** to predict the probability of a URL being malicious.
  - Input: Feature vector from Layer 1.
  - Output:
      * Threat probability (0–1)
      * Confidence level (low/medium/high)

Layer 4: Hybrid Engine (hybrid_engine.dart)
  - Integrates all analysis layers.
  - Responsibilities:
      * Runs feature extraction (Layer 1)
      * Runs static rules (Layer 2)
      * Runs ML classifier (Layer 3)
      * Optional: Behavior simulation (BehaviorEngine)
      * Optional: AI/Rule-based additional detection (RuleBasedAIEngine)
      * Combines scores using weighted fusion
      * Determines final severity (HIGH/MEDIUM/LOW/SAFE) and threat type
      * Generates human-readable explanations and recommended actions

Layer 5: Threat Engine Facade (threat_engine.dart)
  - Singleton interface for the entire engine
  - Loads models and initializes all layers
  - Accepts **ScanSettings** from the UI:
      * phishingSensitivity
      * httpSitesWarning
      * scriptAnalysis
      * adReductionAnalysis
      * adDensityLevel
      * autoRecheckScans
      * sharingConfiguration
  - Provides a single async method `analyze(url, settings)` returning the full threat report.

---

3. Current Models and Engines
-----------------------------

- **Logistic Regression (ML)**:
    * Pre-trained model
    * Classifies URL based on extracted features
    * Provides probability and confidence for scoring

- **Behavior Engine (optional)**:
    * Simulates potential URL behavior (e.g., redirects, script activity)
    * Produces a behavior score for fusion

- **Rule-Based AI Engine (optional)**:
    * Applies additional AI or rule-based heuristics
    * Produces an AI score for fusion

---

4. Scan Output
--------------

Each scan returns a structured report:

- `url` – The URL analyzed
- `timestamp` – Scan date & time
- `scan_result` – Detailed analysis including:
    * `risk_score` (0–100)
    * `severity` (HIGH, MEDIUM, LOW, SAFE)
    * `threat_type` (phishing, suspicious, ad_tracker, benign)
    * `explanation` – Plain English description
    * `detected_threats` – List of threats from static rules
    * `actions` – Recommended user actions
    * `ml_confidence` – Confidence from ML model
    * `behavior_score` – Optional behavior engine score
    * `ai_score` – Optional AI engine score

---

5. Threats Identified
---------------------

The current engine can detect:

- **Phishing URLs**
- **Suspicious URLs** (structurally unusual or unknown)
- **Ad trackers** (URLs containing tracking parameters)
- **General safe URLs** (benign links)

Optional layers enhance detection:

- **Behavioral anomalies** (redirects, suspicious scripts)
- **Additional AI/rule patterns** (custom rules or heuristics)

---

6. Requirements Met
-------------------

- Modular multi-layer design
- Singleton interface for Flutter integration
- Async API for easy UI calls
- Incorporates user-defined scan preferences
- Combines static, ML, behavior, and AI layers
- Generates detailed explanations and actionable guidance
- Supports expansion with additional models or heuristics
